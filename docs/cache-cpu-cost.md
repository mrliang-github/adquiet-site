# 缓存、计算与访问成本

规范：WEB-CACHE-CPU 1.0。平台：Cloudflare Pages，项目 `liangxiaoai`。本次状态为本地实现与验证，未推送、未部署；不将开发或本地预览视为 CDN/线上容量证据。

## 路由与计算边界

| 路径 | 实现与缓存 | 请求时计算 |
| --- | --- | --- |
| 首页、介绍、产品、文章、公司查询页及指南 | Astro 静态 HTML，沿用 Pages 默认缓存与 ETag | 无应用函数；查询在浏览器执行 |
| `/data/little-giants.json`、`/data/unicorns.json` | 兼容已有静态数据地址，沿用默认重验证 | 读取固定文件 |
| `/data/agents/` | 静态使用说明；不预加载完整快照或分块 | 无应用函数 |
| `/data/agents/manifest.json` | 小清单，浏览器 300 秒、共享缓存 3600 秒 | 读取固定文件 |
| `/data/agents/v1/{dataset}/{content-sha256}/…` | 按实际发布内容生成版本；浏览器一年 immutable，沿用 Pages 内部分发机制 | 读取固定文件 |
| `/data/agents/schema.json`、`README.md`、`/llms.txt` | 静态字段与读取说明，浏览器缓存 3600 秒 | 读取固定文件 |
| 不存在路径 | 预生成 `404.html`；本次给错误页增加 noindex | 无应用错误页函数 |

没有新增账户、积分、私有数据、数据库、模型调用、实时抓取或后台轮询，也没有动态例外。公开下载的 CORS 与长缓存只覆盖明确的数据路径，不添加全站共享缓存规则。生产量测仍需核对正确部署 SHA/ID、函数路由与 CDN 行为。

外部 Agent 在自己的运行环境中分析数据。建议并发不超过 2、最多每小时主动检查一次清单；这些是客户端约定，**不是强制限流**。以后若增加服务端 AI 分析或认证接口，必须单独评审预算、权限、并发、超时及缓存隔离。

## 构建与自动检查

`cache-cost.config.json` 保存关键路由、产物与体积预算。`scripts/cache-cost-integration.mjs` 从 Astro 6.4.8 的 `astro:routes:resolved` 获取真实路由元数据，在 `astro:build:done` 调用检查器：

- 检查公开 page/endpoint 均预渲染，动态例外表为空，发布目录没有 `_worker.js` 或 Functions 目录。
- 检查关键公开页、两份原有 JSON、Agent 页面/说明/清单和真实 404 文件；404 必须含 noindex。
- 对清单中的每个快照、索引和分块检查真实文件、字节数、SHA-256、版本、来源记录 ID 和分块内容还原；同时检查缓存路径规则。
- 清单上限 16 KiB、索引 128 KiB、完整快照 8 MiB、分块 256 KiB / 100 条、Agent 数据文件上限 500。
- 审查记录写到 Astro cacheDir；受管任务可指定 `CACHE_COST_REPORT` 保存唯一证据。它不进入公开部署目录。

检查随普通 `astro build` 执行，因此 `npm run build`、`npm run build:pages` 与 GitHub Actions 均会执行。CI 另运行 Agent 数据契约测试。以上自动检查只验证静态边界、产物与文件预算，不能替代平台剩余额度或线上 CDN 命中检查。
