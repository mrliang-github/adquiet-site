![GPT-5.6 来了，但 Codex 没了？](https://img.liangxiaoaitool.top/2026/07/gpt-5.6-codex-cover-v1.png)

这篇原本准备周五发。

结果周五没发出来，一拖就是两天。

现在 GPT-5.6 已经发布两天了，这篇也不能再按发布当天的稿子发。好处是，这两天是真的一直在用，文章里终于不只有功能介绍了。

从本机记录粗略算下来，GPT-5.6 发布到现在，我已经跑了 20 多亿 token。中间账号又重置了两次，给的额度还是很大方。

这次优化给我的感受，也不只来自跑分。

GPT-5.6 确实好用了不少。很多以前容易写得很完整、但读起来不像人会说的话，现在开始能把话说明白了。这两天，真实项目和内容任务也一直在里面跑。

但这次更新最容易让人看不懂的地方，也正好出现在界面上：

**GPT-5.6 来了，原来那个独立的 Codex App 好像没了。**

## Codex 没消失，只是被放进了 ChatGPT

原来单独打开的 Codex App，更新后变成了新版 ChatGPT 桌面端。

左上角可以切换 Chat、Work 和 Codex。原来的项目和对话还在，只是三个入口被放进了同一个应用。

所以标题里的“没了”，说的是独立的 App 壳子。

Codex 的能力没有消失，反而被放到了 ChatGPT 更核心的位置。

![新版 ChatGPT 桌面端可以切换 Work 和 Codex 模式](https://img.liangxiaoaitool.top/2026/07/chatgpt-work-codex-switch.png)

以前我会把 ChatGPT 和 Codex 当成两个工具。

ChatGPT 用来讨论需求、判断方向、改文案。Codex 用来读项目、改文件、跑命令、做验证。

现在它们更像同一个工作台里的不同模式。我不需要先想该打开哪个 App，只需要在左上角切一下。

这个变化看起来只是少开了一个应用，实际用起来顺了很多。尤其是前面已经聊过的内容，不需要每次换到 Codex 后再从头解释一遍。

## 用了两天，我觉得这次优化是有效的

GPT-5.6 发布当天，大家最容易讨论模型能力、跑分、Sol、Terra、Luna 这些档位。

这些当然重要，但我连续用了两天以后，更明显的感受是：它终于开始像一个完整的工作台了。

一边可以聊需求、看资料、整理判断，另一边可以直接进入真实项目执行。中间少了复制粘贴，也少了很多上下文丢失。

ChatGPT 网页对话现在还可以通过 `Add to task` 加入 Codex 任务。

我可以先在普通 Chat 里把需求和限制聊清楚，确认以后，再把整段对话交给 Codex，让它基于这些上下文去改文件、跑测试、验证结果。

![ChatGPT 网页对话可以通过 Add to task 加入 Codex 任务](https://img.liangxiaoaitool.top/2026/07/chatgpt-add-to-task.png)

以前最麻烦的是交接。

前面为什么要做、哪些方案已经排除、什么不能改，我经常要重新说一遍。漏掉一个限制，后面的执行方向就可能偏掉。

现在 Chat 和 Codex 被放到一起以后，这段路确实短了。

再加上 GPT-5.6 本身的表达比之前自然，很多地方开始愿意说人话了，这次升级带来的变化就很具体了。

它是在把讨论、整理和执行放进同一套工作环境里。

## 放进同一个 App，不代表共用同一个额度

这里要单独说一下。三个入口摆在一起，很容易让人以为 Chat、Work、Codex 已经合成同一个额度了。

答案不是。

按 OpenAI 目前的官方说明，可以这样理解：

- 普通 Chat 有自己的消息和模型使用限制；
- Work 和 Codex 走的是 Agent 执行额度，也就是 agentic usage；
- Work 和 Codex 彼此按同一套使用结构计算；
- API Key 调用仍然按 API 价格单独计费。

最容易误解的就是第一点。

Chat、Work、Codex 虽然已经放进同一个 ChatGPT 应用，但普通 Chat 和 Work/Codex 不是同一个额度池。

如果你先在 Chat 里用 GPT-5.6 把问题聊清楚，再把确定的任务交给 Codex，Chat 阶段不会直接去扣 Codex 的 Agent 执行额度。

但任务一旦进入 Work 或 Codex，就要看 agentic usage。Work 和 Codex 之间也不是各送一份独立额度，它们走的是同一套使用结构。

所以更准确的关系是：

```text
普通 Chat：单独的消息和模型使用限制

Work + Codex：Agent 执行额度

API：单独按量计费
```

界面合并了，额度没有全部揉成一个池子。

## 两次重置是我账号上的真实情况

这两天我的账号又重置了两次。

这次不用猜了。

7 月 11 日，OpenAI 的 Codex 负责人 Tibo 在 X 上公开说，他们已经重置了 Codex 和 ChatGPT Work 的使用额度，当天晚些时候还会再重置一次。

大约 20 个小时后，他又发了一条：面向所有 ChatGPT Work 和 Codex 用户，再来一次 usage limit reset，接下来 30 分钟内陆续生效。

他也解释了原因：上线后的流量增长太快，他们以前从没见过系统流量以这么快的速度上涨。

![OpenAI Codex 负责人 Tibo 宣布为 ChatGPT Work 和 Codex 用户重置使用额度](https://img.liangxiaoaitool.top/2026/07/gpt-5.6-codex-work-usage-reset-tibo.png)


我已经跑了接近 20 亿 token，中间还能继续重置。对于一个把工作需求、自己的产品、内容和数据分析都放在 Codex 里的人，这个额度确实给得很大方。

之前我写过一句话：

> Claude 不说话，就是一味地封号；Codex 不说话，就是一味地重置。

GPT-5.6 发布以后，这个感觉又明显了一次。

能多用，当然舒服。

但额度大方只是其中一部分。真正让我愿意继续用的，还是它这次确实变得更顺了：入口更统一，上下文交接更短，模型表达也比以前自然。

## Chat、Work、Codex，我现在只看任务要做到哪一步

三个模式放在一起以后，我不会花太多时间研究每个按钮的定义。

我现在的判断很简单：

需要讨论、判断、写作，用 Chat。

需要调研、整理资料，最后交付文档、表格、PPT 或网站，用 Work。

需要进入真实项目，改代码、跑命令、测试和交付，用 Codex。

真正需要记住的只有额度边界：Chat 单独算，Work 和 Codex 算 Agent 执行额度。

至于 Sol、Terra、Luna 怎么选，我也不会每次都追求最高档。日常任务用合适的档位就行，复杂重构、长链路排查和真的需要多轮检查的任务，再把模型和推理强度拉高。

## Codex 没了，但又没有真的没

现在再看这个标题，“Codex 没了”只说对了一半。

独立的 Codex App 入口正在消失。

但 Codex 没有被削弱，它开始变成 ChatGPT 里的执行层。

这两天接近 20 亿 token 用下来，我对 GPT-5.6 的感觉比发布当天更好。能力确实变强了，很多地方也终于开始说人话了。

而且 Chat、Work、Codex 合在一起以后，我不需要再把它们当成三套互相割裂的工具。先把事情聊清楚，再整理，再进入项目执行，这条链路现在顺了很多。

额度关系也比界面看起来更清楚。

记住一句就够了：**入口合并，不等于额度全部合并。普通 Chat 单独算，Work 和 Codex 走 Agent 执行额度。**
