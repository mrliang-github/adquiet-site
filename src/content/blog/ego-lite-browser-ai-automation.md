平时用 Claude Code、Codex 或者 Antigravity 干活的时候，只要让它去操作网页，用起来马上就别扭了。

以前基本只有两种办法。一种是让 AI 直接连本地正在用的 Chrome，虽然有现成的登录状态，但它一跑起来就自己切标签页、滚屏幕、抢鼠标，它干活的时候我基本没法碰电脑；另一种是拉起无头浏览器（Headless）在后台跑，倒是不打扰人了，可每次打开都是干干净净的空白环境，一碰到需要登录的后台或者滑块验证就直接卡住。

最近一两个月，我一直在用 GitHub 上涨到 `2.3 万+ Star` 的 **`ego(lite)`**。平时让 AI 干网页的活，它应该就是现阶段浏览器自动化的版本答案，也是目前最好用的一台“AI 打工浏览器”。

一开始装它，我只是想给 AI 找台专门在后台挂账号干活的副机，自己平时看网页还是用 Chrome。结果用着用着，好几个常去的后台都在里面登稳了，现在连我自己日常刷网页也慢慢往 `ego(lite)` 上转了。

## 不抢鼠标也不掉登录，它本来就是按人机共用做的

公开网页其实用不着开浏览器自动化，抓个文本就能看；真正非得让 AI 上浏览器去点的活，多半都在登录墙后面。

`ego(lite)` 是新加坡团队 Citro Labs 做的，免费提供 macOS 和 Windows 桌面版（他们还有一个还在排队的完整版个人 Agent 平台叫 `ego`）。它没再去折腾怎么给 Chrome 装插件、配调试端口，干脆基于 Chromium 自己做了一个让人和 AI 共用的浏览器。

装好第一次打开时，它会问你要不要把 Chrome 或 Edge 里的家当搬过来。点一下确认，平时登录好的网站会话、Cookie 和书签就能直接用上；同时它还会把配套的 `ego-browser` 技能写进本机 Claude Code、Codex、Cursor、Antigravity 这些工具的目录里，装完就能直接叫起来干活。

用起来最省心的，还是它把人和 AI 的操作区域拆开了。你在自己窗口正常查资料、看网页，终端里给 AI 派完任务，它会在浏览器里单开一个叫 `Space` 的后台工作区自己跑。

像这两天我让它在后台打开已经登录好的 X，调内置 Grok 翻了近百条中英文原帖核对信息，或者把写好的文章挨个填进几个技术社区的草稿箱里，我前台的鼠标和正在看的标签页一点不受影响。想看它跑到哪一步，随时切过去瞄一眼就行；真遇到二次验证或滑块过不去，它也会按内置的 `handOff` 机制先停下来，等我手动点完再继续。

## 跑网页又快又省额度，主要是省掉了来回传图

除了不抢鼠标和自带登录态，如果之前试过靠截图猜坐标的方案，或者用过传统的单步浏览器 MCP，换到 `ego-browser` 之后，能明显感觉它跑得快很多。

以前那种慢，多半是“走一步问一步”拖出来的：点一下按钮、把整个页面传回去、等大模型想一轮再填下一个框，十几步操作来回拉扯好几分钟，额度也跟着烧掉不少。

`ego(lite)` 换了另一套路子。一方面，它在定制的 Chromium 内核里直接把网页压成几百 Token 的精简文本快照（Snapshot），给输入框和按钮编好 `@1`、`@2` 这样的序号，连一般脚本很难读进去的跨域嵌套 `iframe`、Shadow DOM 和 Stripe 这类第三方内嵌组件也能直接定位，不用反复截图猜坐标。

另一方面，既然调用它的本身就是会写代码的 Agent，它干脆走代码批处理（Heredoc）：AI 看清页面结构后，直接写一小段 Node.js 脚本，把打开网页、填表、点击、等加载和抓数据一口气跑完，省掉中间一轮轮来回通信的开销。

官网上挂过一组 **31 个真实网站复杂任务**的实测对比（`Real-World Bench`，统一跑在 `pi` 框架和 `gpt-5.6-sol` 最高思考档下，所有子条件全达成才算完全成功）：

![官方 Real-World Bench 31 项真实网站复杂任务实测对比](https://img.liangxiaoaitool.top/2026/11/ego-lite-20261118-02-benchmark.png)

**`ego-browser` 的完全成功率到了 `93.50%`，单个任务平均只要 `398 秒`、成本 `$1.64`**——对比同场测试的 `playwright-cli`（`71.00%` 成功率 / `648 秒` / `$3.42`）和 `chrome-devtools-cli`（`61.30%` / `$4.95`），成功率高出一块，耗时和成本也都砍掉一大截。这是官方自己公布的测试数，肯定多少偏向自家强项，但耗时缩短、Token 省下来这个方向，跟我这一两个月自己跑任务的体感是能对上的。这两天在 X 上也能看到不少开发者在聊类似的用法：桌面软件留给 Computer Use 去点，一旦进了网页，还是交给 `ego(lite)` 顺手。

## 真装来用之前，这 3 件事别搞反了

现在网上推荐它的文章已经不少了，但有几个关键细节经常被写错。打算装来试水的话，提前知道这三件事能少踩点坑。

第一，**防串号要靠 `Profile`，别指望 `Space`。** 好多文章看到官方宣传“隔离 Space”，就顺手写成每个 Space 的 Cookie 也是分开的。其实不是。`Space` 隔离的只是窗口标签页和鼠标控制权，**同一个 Profile（抽屉）底下不管开多少个 Space，登录态和 Cookie 全都是互通的。** 假如你在同一个平台上有两个号，千万别在同一个抽屉里新建个 Space 去扫码，一样会把前一个号顶下线；真要物理隔开，得老老实实建不同的 Profile。

第二，**开源的只是技能层，高权限动作最后一步还是自己点。** GitHub 上 `citrolabs/ego-lite` 挂着 MIT 协议，但开源的只有 `ego-browser` 技能和周边脚本，浏览器客户端本体是免费闭源的（不用注册账号，数据也只存在本地）。另外登录态本质上就是你的账号凭证，平时在后台让它查查资料、填填草稿没什么问题，真碰到付款、删数据，或者点下“公开发布”这种改不回去的操作，还是定好规矩让它停在确认页上，自己看一眼再点。

第三，**拿它彻底替掉 Chrome 当唯一主力，现阶段还有点小别扭。** 这也是我为什么只是慢慢往 `ego(lite)` 转，暂时还没把 Chrome 彻底关掉的原因。客户端目前还在 `0.6.3.x` 阶段，看它 GitHub 上的 Issues 也能发现不少细节毛刺，比如 macOS 新版把 `Cmd + Shift + C` 绑成了复制页面链接，正好撞上很多人习惯的 DevTools 审查元素快捷键（Issue `#733`）；历史记录里现在也还不区分人和 AI 打开的页面，跑完一轮后台任务，历史记录会被刷满（Issue `#714`）。拿它专门给 AI 当后台打工浏览器已经很稳了，日常浏览可以慢慢迁移。

## 最后

如果平时只是打开网页聊几句天，没必要专门换个新浏览器；但只要你已经在用 Claude Code、Codex、Cursor 或者 Antigravity 跑实际工作流，经常需要让 AI 去登录后面的页面干点杂活，装上 `ego(lite)` 试一次，大概率就会一直留着它。

至于我怎么拿它的多抽屉和 `Space` 来管自媒体账号、铺多平台草稿，下篇分享我的自媒体流程时再展开聊。
