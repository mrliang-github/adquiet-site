Codex 一周重置 4 次额度，我推进 2 个 App，把送审自动化了

这一周 Codex 重置了 4 次额度。我用它推进两个 App，从商店资料一路做到提交审核。

2026.07.17AI 产品 · Codex · App Store

从周末到现在，Codex 已经给我重置了 4 次额度。

并且把小时额度也取消了，只剩一个一周的额度窗口。所以这几天，大家都在猛猛蹬 ，是的，这就是天天给我们重置额度的男人：Tibo

按本机日志粗算，从 7 月 12 日到现在，已经用了超过 37 亿 token。两个 App 这一轮的活跃开发时间合计约 50 小时。

最后的结果是，两个 App 都已经提交给 Apple，正在等待审核。同时，我也把一条以前很碎的上架流程跑通了。

这两个 App，都来自商店数据

我之前下载了 App Store 多个地区的数据，再从里面找那些下载频率高、评价偏低、很久没有更新的 App。

这些产品已经证明有人用，但用户评价和更新状态又说明，它们还有不少问题没解决。我让 GPT 继续分析评论、功能和竞品策略，把高频吐槽整理成新需求，这才有了这两个 App。

两个产品前后优化了将近两个月，中间还穿插了其他项目。开发也没有按着最初的需求一路写到底，而是一边跑、一边测，再反过来改需求、页面设计和交互细节。

代码做完后，Codex 继续往后做

因为数据分析、产品文档、设计调整、开发和测试都在 Codex 里完成，它对项目已经很熟悉。代码测完以后，我没有再去给另一个工具从头解释产品。

我把 App Store 营销图这一段做成了一个 Skill。它先读项目文档、真实界面和竞品策略，整理产品关键词、副标题、描述和营销方向，再为每张图确定一个主题和价值点。然后我另开一个任务，让它根据真实 App 截图生成可上传的营销图。

图片和文案准备好后，Codex 直接连接 App Store Connect API，把截图、关键词、描述和审核资料上传到 Apple 后台。API 还不能处理的字段，就打开网页，用 Codex 的浏览器能力继续填完。隐私政策、支持页面和审核需要的文档，也是在同一个项目里生成和检查。

整条流程现在变成了：

App Store 数据 → 需求分析 → 产品文档和设计 → 开发测试 → 营销文案和图片 → API 上传 → 网页补齐 → 提交审核

下一个 App，可能只需要两三天

这两个 App 现在都在等待 Apple 审核，还不能说已经在商店正式上线。

但这条流程跑完以后，如果再做一个同类的新 App，我觉得有机会在两三天内把它推进到可提交审核的状态。Apple 实际审核需要多久，这部分我控制不了。

这几天我还顺手优化了几个以前的 App。这 4 次额度重置，最后换来了一条完整路径：Codex 跟着一个产品，从数据起点一路走到 Apple 后台。
