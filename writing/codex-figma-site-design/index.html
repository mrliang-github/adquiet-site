免费模板搭完独立站后，我用 Codex + Figma 做了自己的页面设计

免费模板虽然完整，却不一定适合产品、竞品风格和询盘路径；于是先用 Codex + Figma 整理自己的页面设计。

2026.06.15独立站 · Figma · 页面设计

上篇我写了自己用 Codex 搭了一个 WordPress 独立站。

那篇主要解决的是：先让网站跑起来。

服务器、WordPress、域名、SSL、后台配置，这些事情处理完以后，网站至少能打开了。

但网站能打开以后，我没有马上让 Codex 继续改首页、做产品页、补详情页。

我先停了一下。

因为我这次不是从空白页面开始做的。

我一开始直接用了一个免费模板。

这个模板让网站很快有了完整页面。首页、产品区块、按钮、移动端布局都先有了，看起来也不是不能用。

但真把自己的产品放进去以后，我很快发现，它和我要做的站不完全匹配。

有些区块看起来完整，但不适合我的产品展示。

有些地方要加内容，比如产品卖点、询盘入口、FAQ。

有些地方又要删掉，不然页面会很像模板站。

再往下改，还会碰到另一类问题：有些组件只有部分免费，想继续用就要付费；有些样式后台能调，但只能调到某个程度。

而且外贸站不可能只看一个模板就定稿。

你肯定要多看竞品，看别人怎么放产品图，怎么写 CTA，怎么安排产品列表和详情页。

这些东西一加进来，真正麻烦的地方就出现了：

后面越改越乱。

今天首页参考一个网站，明天产品页参考另一个网站，后天详情页又换一种排版。每一页单独看可能都还行，但放在一起，就不像同一家公司的网站。

放到外贸站里，这件事会直接影响买家信任。

买家第一次进来，不会研究你用了什么工具。

他只会很快判断几件事：

  • 这个公司靠不靠谱？
  • 产品信息清不清楚？
  • 询盘按钮好不好找？
  • 手机上能不能正常看？
  • 点进产品页以后，感觉是不是还在同一个网站里？

所以我这次没有直接对 Codex 说：

继续帮我做几个好看的页面。

我先做了一件更慢、但后面更省事的事：

先把网站的页面设计整理进 Figma。

下面这张就是我当时整理的一部分。

它不是完整品牌手册，更像一张页面设计里的规则表：颜色、字体、按钮、产品卡片、状态、检查项，都先放在一个地方。后面再改页面时，不用每次重新猜。

模板能起步，但不能替你做判断

很多人做独立站，会先用 Shopify、WordPress 主题，或者各种建站模板。

这个选择没问题。

模板最大的价值，是让你不用从零开始。导航、首页区块、产品列表、购物车、移动端适配，这些基础东西它都帮你准备好了。

但模板也有一个边界：

你能改的东西，通常取决于这个模板本身给了哪些设置。

改颜色、换字体、拖动几个区块，这些一般不难。

但如果你想把产品卡片改成更适合自己行业的样子，想把询盘按钮换到更顺手的位置，想让详情页更贴近你的销售逻辑，事情就不一定简单了。

对完全不懂网站的人，这个问题可能表现为“我不知道怎么改”。

但对有一点设计基础、或者自己做过网站的人，感受反而会更明显：

你知道自己想要什么，也看得出模板哪里不对，但它就是不给你那么多调整空间。

很多时候，你会卡在一个很尴尬的位置：

  • 模板能用，但看起来不像自己的业务；
  • 后台能改，但只能改到某个程度；
  • 你有自己的判断，但模板不一定给你发挥空间；
  • 再往下改，就要碰代码、找开发，或者担心以后主题更新出问题。

我看 Shopify 官方文档时，也能看到类似边界。

主题编辑器可以调整设置、增删和移动内容区块；但如果主题没有提供你想要的设置，就要去改主题代码。而改代码需要懂 HTML、CSS 和 Liquid，复杂定制也不是官方支持能完全兜住的范围。

所以我这次先做 Figma 页面设计，不是觉得模板不好。

模板适合让网站先跑起来。

Figma 这一步，是为了在模板之上先想清楚：哪些地方必须像我自己的业务。

我先定了几个最容易乱的地方

这套东西不用做得很复杂。

小团队、个人项目、早期独立站，一开始也不需要完整品牌手册。

我先定的是几类最容易影响买家判断的东西。

第一类是产品展示。

比如产品图用什么比例，产品卡片里放哪些信息，标题最多几行，规格参数要不要露出，按钮放在哪里。

如果产品不是普通零售品，而是偏外贸、B2B、供应链这种场景，默认模板的产品卡片经常不够用。

它可能能展示图片和标题，但不一定能把规格、应用场景、询盘动作讲清楚。

第二类是询盘入口。

按钮文案用 Get a Quote 还是 Contact Us，首页、产品页、详情页的询盘按钮要不要统一，表单放在哪里，移动端是否容易点到。

这些会影响买家想联系你的时候，会不会卡住。

第三类是页面结构。

首页先讲什么，产品详情页先放卖点还是先放规格，FAQ 放在哪里，竞品常用的模块哪些值得参考，哪些不适合照搬。

第四类是移动端。

很多外贸站桌面端看着还行，手机上一打开就很乱。首屏图片怎么裁，产品卡片一行一个还是两个，按钮会不会太小，表单会不会太长，这些都要提前定。

这些规则听起来都很细。

但它们加起来，决定了这个网站是不是像一个可靠的公司网站。

我也会把页面稿放在一起看。

首页、产品列表页、产品详情页不要只单独看，要放在同一个画面里比较：产品卡片是不是统一，留白是不是一致，询盘入口是不是还在同一套规则里。

再让 Codex 按规则改页面

真正让 Codex 改 WordPress 页面时，我不会只给一句“帮我做得好看一点”。

这种话太虚。

好看到底是什么？

是产品图统一，还是询盘按钮更明显？

是信息密度更合理，还是移动端不要乱？

这些东西放进 Figma 以后，Codex 才有判断标准。

比如我要调整产品列表页，我会这样说：

请参考 Figma 里的产品卡片、按钮和询盘入口规则，
帮我调整 WordPress 的产品列表页。

要求：
1. 产品图片比例保持一致；
2. 产品标题最多两行；
3. 主按钮统一使用 Get a Quote；
4. 移动端一行一个产品卡片；
5. 不要新增没有必要的渐变、阴影和大圆角；
6. 改完后检查桌面端和移动端。

这时 Codex 的角色就清楚了：

它不是重新设计一套审美，而是按 Figma 里的按钮、卡片、移动端规则，去检查和调整 WordPress 页面。

这对我这种一个人做项目的人很重要。

因为我没有设计团队，也不一定有长期合作的外包。

但至少我可以让每次修改不要从零开始。

以后新增产品页时，可以沿用同一套产品卡片和详情页结构。

以后补 FAQ 时，可以沿用同一套模块样式。

以后做询盘页时，按钮、表单和文案不用重新想。

以后让 Codex 或外包改页面时，也不用每次从头解释一遍网站风格。

这一步解决不了所有问题

当然，Figma 解决不了所有问题。

它不能替你决定产品卖点。

它不能替你写出真正打动客户的内容。

它也不能解决产品资料混乱、图片不统一、SEO 字段没人维护这些问题。

它先帮我解决的是一个更基础的问题：

这个站看起来别像拼出来的。

真正要让独立站能运营起来，后面还要继续解决产品内容维护。

比如产品名、分类、图片、描述、SEO title、SEO description、发布状态，这些东西不可能每次都手动进 WordPress 后台一点点填。

做完这套页面规则以后，我很快发现：

建站是一次性的。

页面规则是为了让网站别越改越散。

产品内容维护，才是长期活。

所以下一篇我会讲，我为什么开始用 Google Sheets 和 Drive 去管独立站产品内容。

不是为了显得流程复杂。

只是如果一个网站后面真的要持续上产品、改图片、补描述、做 SEO，这些东西必须先有一个地方管起来。
